# FLProg_OLED 1.0.1

Библиотека интеграции графических дисплеев в проекты FLProg. Использует **сторонний** драйвер `RT_HW_OLED`, функции `RT_HW_BASE` и базовые типы `Flprog_Utilites`. Драйверы `RT_HW_*` в этой ревизии **не изменены**.

## Возможности

- Устройство дисплея и шина I²C, SPI или параллельный интерфейс KS0108.
- Один `FlprogOledDisplay` может объединять несколько логических `FlprogOledScreen`, каждый экран — несколько виджетов.
- Примитивы: текст, линия, прямоугольник, окружность, стандартные иконки 8×8.
- Значения: целые числа, `float`, строки, логические значения, подписи по спискам.
- Индикаторы состояния и линейный индикатор уровня (`FlprogOledGaudeWidget`, историческое написание API сохранено).
- Неблокирующий цикл `chip.pool(true); display.displayOn(&chip);` с учётом передачи framebuffer средствами RT_HW.

## Основные классы

| Класс | Роль |
|---|---|
| `FlprogOledAbstractChip` / `FlprogOledI2cChip` / `FlprogOledSpiChip` | Настройка контроллера дисплея и шины |
| `FlprogOledDisplay` | Полный framebuffer, передача, перерисовка |
| `FlprogOledScreen` | Группа экранных виджетов с признаком активности |
| `FlprogOledAbstractWidget` | База виджетов и контроль изменений |
| `FlprogOledTextWidget` | Текстовые примитивы |
| `FlprogOledAbstractValueWidget` | Форматирование текста значений, префикса и суффикса |
| `FlprogOledNumberListValueWidget` / `FlprogOledFloatListValueWidget` | Сопоставление чисел с подписями |
| `FlprogOledIconWidget` | Стандартная таблица 8×8 |
| `FlprogOledGaudeWidget` | Линейный уровень/заливка |

## Порядок вызовов

1. Создать объект дисплейного чипа, настроить шину, размер и параметры контроллера.
2. Создать `FlprogOledScreen` и назначить указатели на виджеты через `setWidget(index, &widget)`.
3. Зарегистрировать экран через `display.setScreen(index, &screen)`.
4. В `loop()` сначала выполнить `chip.pool(true)`, затем `display.displayOn(&chip)`.
5. При изменении значения у виджета вызвать его setter. Экран отметит необходимость обновления. Время передачи и готовность устройства контролируются RT_HW_OLED.

`FlprogOledDisplay` и `FlprogOledScreen` **не владеют** объектами экранов и виджетов. Они освобождают только собственные динамические массивы указателей. Объекты рекомендуется создавать статически; копирование этих контейнеров запрещено для защиты от двойного освобождения.

## Поведение 1.0.1

- Все свободные позиции таблиц экранов/виджетов изначально `nullptr`. Допустимо назначать только часть элементов.
- `setWidgetsSize()` сохраняет указатели в остающихся индексах, освобождает прежнюю таблицу и обновляет картинку. При уменьшении размера записи за новой границей теряются из таблицы, но сами виджеты не удаляются.
- `setScreen(index, nullptr)` отсоединяет экран. Рисование повторяется и при выключении одного из нескольких экранов (`screen.isActive(false)`).
- Подписи `setDefaultText`, `setTextItem`, `setTrueText`, `setFalseText` перерассчитываются и при неизменном числовом/логическом значении.
- Стандартные иконки имеют реальный размер 8×8. Неверный индекс пропускается. `setSize()` может задать меньший размер, но значения ширины/высоты более восьми ограничиваются размером исходной записи, чтобы не читать чужую память.
- Усечение значений с `setLength()` делается по границе символов UTF-8, а не по одному байту. Отрицательные координаты сохраняются как знаковые числа; выход за допустимый `int16_t` диапазон ограничивается.
- Интерполяция уровня выполняет промежуточные расчёты в `int64_t`, не переполняя `int32_t` на предельных значениях.

## Совместимость и ограничения

- Сохранены названия публичных классов, методов и констант, включая исторические опечатки (`Gaude`, `Grapfic`, `setAdress`, `setColorBGRt`): их автоматическое переименование нарушило бы генератор FLProg.
- Изменение внешнего интерфейса: копирование контейнеров `FlprogOledDisplay`, `FlprogOledScreen` и числовых списков теперь запрещено; используйте долгоживущие отдельные объекты и ссылки.
- Библиотека использует динамическую память для таблиц указателей, списков значений и `String`. Для малых AVR нужно рассчитывать свободную ОЗУ.
- Внутренние методы и формат протокола RT_HW_OLED не изменялись. Проверьте компиляцию на используемых Arduino Core, а также на реальных дисплеях, особенно SPI/DMA и нескольких активных экранах.
- `setLength(0)` означает нулевую ширину текстового значения, как и в исходном API.
- Режимы работы чипа в основном задаются при первичной инициализации `pool(true)`; изменение аппаратной конфигурации после её завершения требует отдельной процедуры пересоздания устройства.

## Проверки

В каталоге `tests/host` лежит изолированный тест на C++11 со **специальными заглушками**, имитирующими только используемую часть API `RT_HW_OLED`. Запуск на машине с G++:

```bash
bash tests/host/run.sh
```

Ожидаемый результат: `OLED_HOST_TEST_PASS`. Это проверка поведения обёртки, **не** реальная сборка Arduino и **не** тест аппаратного драйвера.
